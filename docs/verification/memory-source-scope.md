## One next regression-sized gap: expired multiline retrieval

The parser already assigns each dated entry a complete `line..end` span, including indented continuation text and closed code blocks. `memoryVisibleText` removes that whole span. In contrast, [withoutExpired](../../server/memory-entries.ts#L70) collects **only `entry.line`** and removes only those header lines. The retained continuations then look like ordinary text. Both `searchableMemoryText` and `topicPassages` call this helper; `withoutSuperseded` afterward cannot identify the now-removed dated header. Consequently an expired topic's continuation can remain in indexed text, lexical/bigram snippets and the semantic input, or a named-topic passage. This is a source-level mismatch, not a runtime reproduction claim.

Existing entry regressions (`server/memory-entries.test.ts`) separately cover multiline parsing and single-line expiration, while the complete-span expiration test is on the prompt/capture path. This supports one bounded proposal: make expiry retrieval filtering respect the existing entry span and add regressions through the existing entry/index/recall seams. Do not redesign storage or add a deletion framework.

Proposed acceptance (future implementation, **not executed here**):

1. In an isolated synthetic topic, put unique continuation and fenced-code canaries under a dated expired header; put a live fact, handwritten line and same-day `until` entry beside it. Expiry filtering must remove the full expired span and count one expired entry while retaining the controls and original file bytes.
2. Exercise actual `syncMemoryIndex`/file search and `buildRecall` with `threadIds: []`, then a topic-alias query. Neither indexed documents nor returned recall may contain either expired canary; a live query must still return its source label. Use a fresh query so history cannot mask the result.
3. Reuse the fake-fetch pattern in embedding-index regressions (`server/memory-embedding-index.test.ts`): capture the actual embedding input, confirm no expired continuation, and preserve stale-hash rejection. No external service or real user data.
4. Cover a day rollover without editing the file, keep superseded and prompt/capture regressions, and retain same-day inclusivity. Use the existing [verification fixture contract](README.md); do not claim helper-only success establishes full prompt delivery.
