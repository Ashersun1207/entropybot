**Current forgetting is not a universal fact-erasure operation.** M1b removes expired entry spans from active-note retrieval; OPT-004 removes expired/superseded entry spans from core prompt and capture-notebook projections. Historical messages, persisted summaries, daily logs, audit journal, backups and independently derived copies have separate lifecycles. Several can still supply an old fact to a model after its current note has changed.

## Bounded future slices without source deletion

These are proposals for controller assignment, not implementation acceptance. None requires a high-risk purge to establish its bounded visibility claim. Choose one consumer boundary per task and retain all existing author/time/audience checks.

1. **Automatic conversation recall suppression.** Start with explicitly selected message/passage identities and an authorized layer/audience scope. Retain source rows and correction history. Suppress whole selected passages before SQL/candidate limits where possible, then defend every FTS/Chinese/fallback result; otherwise hidden top hits can starve legitimate recall. Keep explicit history search/read outside this first claim, visibly documenting that limitation. Do not use a bare global phrase blacklist as a correction resolver.
2. **Compaction and replay projection.** Apply the same scoped policy to raw replay, old summary prose, trusted active constraints, helper input and deterministic fallback. Preserve anchors and lineage even when projected text becomes empty; prevent omitted summaries from causing an unfiltered raw-history fallback. Couple engine resume invalidation to the policy revision so an already-loaded native context is not mistaken for a freshly filtered prompt. This requires controller-owned index/driver coordination, not an isolated helper-only fix.
3. **Explicit model reads of historical notes.** Cover session-search query hits, time-only recent results, session-read full text and supported file-tool views of logs/archive/history. Maintain a separate human provenance view. Current automatic exclusions are already present and should stay. Restrict the promise to controlled model read paths; arbitrary filesystem access remains a limitation unless separately scoped.
4. **Restore/revert/import accuracy.** Begin with a read-only preview of which current corrections/suppression would be displaced by a whole-file revert, snapshot restore or additive import. Then separately specify expected-current-hash conflict handling, suppression reconciliation and imported origin mapping. Keep raw audit/backup bytes intact. Migration policy must cover both workspace and Team formats and cloud/lending recipients; exporting only learned identities cannot stand in for passage-policy transfer.
5. **Relearning and cache coherence.** Use policy revisions on capture/dream inputs and every output channel, including outdated replacements/ideas; recheck after await. For derived search/vector caches, key eligibility to current projected source and policy version; preserve the existing stale-hash and provider identity checks. A small, separate synthetic probe should investigate same-stat/length cache reuse and tidy span behavior before broadening the general-forgetting claim.

Proposed acceptance uses only disposable synthetic sources and fake engines/providers: put an old fact and its explicit correction in separate authorized threads, a summary, log, journal before/diff, import and backup fixture; use a fresh query thread and a query without the unique answer canary. Capture the **actual** newly supplied prompt, replay, tool response and helper/embedding input, including after restart, two compactions, policy change during await and restore/import. Assert that current correction, unrelated facts and source attribution survive while suppressed content does not enter the specific covered consumer. Hash original retained files/records before and after projection. Positive/negative audience cases, Chinese/Latin matching, empty projections, stale source/policy rejection and fallback paths must remain. Existing helper tests or fake final answers alone cannot prove these flows. No such acceptance was executed here.

## Explicit deletion decisions still needed

Actual removal/redaction of historical chat/digests, persisted compaction records, daily logs, journal before/diffs, old backups/safety copies, existing exports, independently imported/remote notes, engine transcripts and provider-side copies requires a user decision specifying owners, identities, versions, retention, undo and recovery behavior. Deleting a whole thread or bot is a larger lifecycle operation, not authorization to delete every copy of one fact. Physical SQLite/WAL/free-page or filesystem/cloud erasure needs its own storage guarantees and evidence; projection, logical DELETE, encryption and feature disabling establish none of those guarantees.

The immediate A boundary should preserve authored history, corrections, journal and backup provenance as audit/recovery evidence. A later user decision can change retention. Avoid turning a retention choice into automatic model eligibility: audit access and model use are separate capabilities.

## Accuracy risks and limits

- **Never remove the correction while retaining an older assertion as current truth.** Blanket passage removal can erase both “X is true” and “X was wrong”; filtering only a correction message or journal row can reverse the meaning of the surviving history. Keep revision/order relationships and make suppression metadata authoritative for model eligibility without quoting the suppressed fact back into the prompt.
- **Undo is whole-file, not fact-scoped.** A journal revert can overwrite unrelated newer facts and restore a pre-correction document. Current revert does not enforce the recorded after-hash or the forgotten matcher. Retain the audit source; preview/check the proposed current state rather than auto-replaying old before text.
- **Structured constraints are another derived copy.** Removing a string from visible summary prose while retaining `compactionSummary` can carry the same constraint into the next compaction. Preserve the explicit empty-state contract and latest correction/cancellation; do not let quoted pseudo-blocks become trusted state.
- **Projection depends on entry identity surviving writers.** Static adjacent risk: [applyTidy](../../server/memory-tidy.ts#L78) drops only expired/duplicate header line indexes and archives expired `raw` headers, whereas the parser can identify multiline spans. If upkeep removes an expired header first, surviving continuation text may lose its expiry identity and evade later projection. This was not dynamically reproduced or fixed here; M1b's retrieval-span repair must not be described as proving all writer paths safe. Keep this as a separate small synthetic regression investigation.
- **Cache identity is not always content identity.** Workspace sync uses stat metadata plus day; bigram cache uses mtime/text length. Same-size/same-mtime edits or equal-length projection changes are a static coherence limitation. Vector hash checks do not prove that the upstream indexed text was freshly projected. No collision probe was run.
- **Suppression is bounded and partial.** Passage matching is lexical, not semantic; synonyms, paraphrases, multilingual variants, continuation-only mentions, different audiences and fresh imported IDs need explicit treatment. Profile state can age out and cloud transfer does not carry the full passage list. Append/prefer intentionally permits remembering again; an expired assertion and an explicit forever-forget request need different semantics.
- **No exhaustive copy inventory or runtime proof.** Locations are source-defined logical paths under DATA_DIR, not inspected user filesystem contents. Arbitrary attachments, generated reports, native engine/provider storage, OS snapshots, downloaded backups and other servers were not enumerated. No assertion is made about actual user content, provider deletion APIs, model obedience or forensic erasure. Controlled read projections cannot promise that a broadly authorized filesystem tool will never read a retained original.

Static maintenance/security self-review followed the note → index/embedding → recall/tool read, history → replay/compaction/capture/dream, journal → revert and backup/transfer → import paths. The proposed work reuses existing provenance and projection boundaries; it introduces no executable behavior, network, permission, dependency or deletion in this delivery.
