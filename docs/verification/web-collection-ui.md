## Product path

Open the actual **Automations** page, choose **New → Manual web collection**, enter a name, choose an existing bot and enter one complete HTTP/S URL per line. The alternate **Set up yourself** menu contains the same explicit collection type. No model is needed to create or run this type.

The editor uses the existing BotPicker, modal styles and useBotEditor POST/PATCH transport. Input is finite (1–100 nonblank lines; 8192 characters per URL), rejects malformed URLs, credentials, whitespace, backslashes and markup, removes fragments, and preserves duplicate entries. It never truncates a list. New plans have the typed `web-collection` kind, version 1, page/attempt limits equal to the list length, 1 MB per page, 10 MB cumulative and 30 seconds. Edits preserve the saved limits and reject a larger list that exceeds them. Existing schedule metadata stays present but disabled; collections always save `enabled:false`, `runOn:maus`, `target:bot`, with no checks, startup, continuity, brief delivery or attachments. Saving sends no run request. There are no time/cloud/room/check controls for collection. Ordinary editors remain unchanged apart from extracting their original BotPicker into a shared focused component.

A collection row opens the actual EventDetails, including its existing protected manual action, exact submitted run, uncertainty explanation, Retry, acknowledged replacement and recent history controls. Collection details and rows omit enable/resume controls. Run output is projected to page/unique counts and report availability without showing the server path. No legacy run fallback or automatic recovery POST was added.

The report child only reads the proposed `/api/routines/:routineId/runs/:runId/collection-report` route on an explicit View report click. Its local runtime validator structurally follows the planned `CollectionReportResponse`; it does not create or edit the other writer's shared type. Before final acceptance, import/align the accepted shared contract and run the full real endpoint journey. Responses are scoped by exact run, cancelled on unmount, shape/count/hash checked, and rendered as escaped plain text in collapsed source sections. Each source preview is capped at 20,000 characters with a visible notice. No Markdown, HTML, image, active link, server path fetch, arbitrary source fetch or file opening is used by this child. Missing, denied, unverifiable and general load errors use distinct fixed localized text. Report-fetch unit tests use synthetic transport and do not qualify the server endpoint.
