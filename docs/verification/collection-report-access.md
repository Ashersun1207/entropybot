# Authorized collection report reads

`GET /api/routines/:routineId/runs/:runId/collection-report` returns `CollectionReportResponse` from `shared/collection-report.ts`:

```json
{"version":1,"pages":2,"unique":1,"hash":"<64 lowercase hex characters>","sources":[{"url":"https://synthetic.invalid/page","text":"<p>literal inert text</p>"}]}
```

The response is a flat object, with no wrapper, private path, request ID or binding. No query parameters or client paths are accepted. This is authenticated JSON, not an attachment, file link or HTML resource. Render source strings as escaped text; do not feed them into HTML or Markdown renderers that load images or construct file links. Hashes and published summary paths remain metadata and confer no authority.

The existing app authentication, workspace authorization, client scope and member policy gates execute before the route module. Only this exact GET shape is added to CLIENT_ALLOW. Service loopback is refused. An Authorization header that did not authenticate a paired session is explicitly refused even on owner loopback: the general gate otherwise ignores unrecognized non-session bearers. Public bot API/internal capability tokens have no alternate path. Owner loopback retains the existing owner trust contract; a paired client with access can read. The retained run must match both URL IDs and pass existing routineRunVisible checks. Its bot must still exist; execution/results threads are required and all recorded execution/results/source threads must still belong to that same bot and remain visible. Routine deletion retains readable history when the run and its audience survive; run or bot deletion refuses. A changed current routine cannot replace the run snapshot or broaden its authorization.

The manager exposes only the original HTTP request ID resolved by its existing unique manualForRun receipt. The reader derives the private collection-reports root and SHA-256 run/routine filename, validates the original plan receipt binding and completed artifact receipt, and never parses path/hash out of the published message. Publication pending/posted metadata is not used for authorization or verification, so the independent backend posted-state correction does not alter this contract.

Reads require a canonical non-symlink private root and regular single-link artifact. The reader opens O_NOFOLLOW|O_NONBLOCK, compares path/descriptor identity, mode, size and change metadata before/after bounded fd reads, checks root/parent identity and containment again, verifies exact byte hash, fatal UTF-8, strict schema, immutable binding, counts, source order/dedup and per-page byte bounds. The hard cap is 61,000,000 bytes (JSON escaping can expand the collector's 10 MB text budget); a smaller plan-derived bound also applies. Message-file helpers authorize Markdown-referenced files in conversation roots and do not bind collection completion/request/plan records, so the endpoint does not extend their root permissions or repurpose them.

Errors are fixed bounded JSON: 400 collection_report_query; 404 collection_report_not_found; 409 collection_report_unavailable (no original request/completion) or collection_report_invalid (file/receipt/hash/schema verification failure). The existing authentication gates can return their existing 401/403/404 errors first. Responses use private, no-store and nosniff. No URL fetch, provider call, report repair, file href or mutation occurs during a read.

## Maintenance and limits

No dependencies or install hooks changed; node_modules is the existing engineering-foundation symlink. Scope is read-only and adds no network, process, credential, configuration, Keychain, frontend or scheduler capability. Routines gains one read-only receipt accessor; index gains the route import/registration; request-auth gains one exact client GET allow rule. Existing size budgets and correctness guards remain intact.

The baseline completion receipt binds bytes, identity and plan, not an inode retained since creation: an identical-byte replacement completed before a request cannot be distinguished and has identical inert content. Replacement during the read is rejected. Checks do not provide a kernel-level deadline against arbitrary remote/filesystem stalls or detect an attacker that can atomically replace both trusted SQLite receipts and private files. Full production Team Cloud person-audience integration, real sites/TLS, renderer/Electron and packaged-platform behavior remain outside this isolated evidence. No push/build/install or active-branch rebase occurred. Controller must combine backend corrections serially and independently review the final source.
