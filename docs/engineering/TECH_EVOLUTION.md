# 技术演进与替换规则

目标是降低成功完成任务的总成本和维护责任。先固定问题与当前实现的调用边界，再比较一个成熟机制；现有代码不是必须保留的理由，流行框架也不是必须引入的理由。

每次只选一个切片：模型协议适配、工具/MCP 生命周期、持久步骤、网页动作或能力包。使用独立 worktree；冻结候选、既有用户数据及其他活跃任务不变。源码、依赖、引擎、模型目录和原生资源分别更新、验收，避免一次实验混合多个版本变化。

## 决策记录

每项实验在对应结果文档记录以下内容，本页只保存通用规则。

| 项目 | 必填内容 |
|---|---|
| 问题与基线 | 实际症状、调用者/接口、固定源码提交、原有回归、已测与未测的成本 |
| 候选来源 | 精确版本/SHA、包与目录许可、维护状态、依赖/安装脚本、运行时与默认网络/遥测/Gateway路径 |
| 保持的契约 | 数据格式与已发行兼容、身份与权限、审批、凭证、工具scope、取消与资源关闭、错误分类、流事件、用量和预算 |
| 同条件实验 | 同输入、机型、模型/工具版本和网络条件；先假模型/合成任务，记录失败案例和多次分布，不用README性能数字替代实测 |
| 总成本 | 本地准备、资源/进程、端到端成功率、人工补救、已知/未知费用、适配与组合验证成本 |
| 结论与退场 | 接受/不采用/待补证据；新增与删除代码、测试、依赖及维护责任；具体回退提交和旧实现退出条件 |

## 通过与停止

正确性、权限、数据兼容和许可是前置门槛。通过后才比较净收益；不能通过删除断言、放大体积预算或降低授权检查来制造收益。候选不能等价或无净收益时，不合入并保留原因，这也是有效实验结果。

- Pi MCP 等协议能力必须同时覆盖宿主的 scope、审批、ask_user、凭证文件、错误和关闭边界；缺少任一能力就不能直接删除宿主策略层。
- 恢复步骤要区分本地状态与外部效果。外部已接受但结果未知时先核实，不因恢复而盲目重发；预算不能在重试/恢复时无声清零。
- 连接复用保持身份、凭证、工作区、版本和权限撤销语义；缓存提速不能变成跨bot共享秘密。
- 包体、首次准备、离线能力、进程RSS与下载压缩大小分别测量；更换桌面壳不自动消除Node/浏览器/原生工具或凭证迁移责任。
- 同一问题连续两次修复未解决时停止盲目重试，回交证据与解除条件；可继续无依赖的已授权任务。不创建常驻演进引擎或无限更新循环。

接受后只替换对应层，删除已被行为回归证明等价的旧实现，保留必要兼容和回退路径；不能长期维护两套agent loop、调度状态、浏览器owner或记忆真源。最终组合验证、独立审查与 [维护记录](MAINTENANCE.md) 完成后才算集成。实验原型不自动成为产品交付，源码通过不等于安装/发布批准。

具体任务授权与禁令以主控项目 `docs/EXECUTION_PLAN.md` 和用户最新指令为准，本页通用流程不扩大构建、安装、发布或 live 调用授权。

依赖更新工具只生成候选与报告；CI稳定并测过成本后才安排分组更新，不默认自动合并。用户凭证、真实聊天、记忆与Keychain不进入CI或实验fixture，真实模型实验必须另有明确预算与授权。
